# 3D 象棋《楚河漢界：名將對弈》企劃提案（草案 v0.1）

> 狀態：討論中，尚未開工。標記 ❓ 的地方需要你拍板。

---

## 1. 一句話概念

一款瀏覽器即可遊玩的 3D 中國象棋。開局前雙方各選一個「國家／陣營」，整副棋子都由該國的歷史名人擔任；
滑鼠停在棋子上可以看到人物小傳和他的招牌絕招；**誰吃掉對方的將帥，就由誰放出自己的全畫面絕招**作為終局演出。

---

## 2. 遊戲模式

| 模式 | 說明 | 技術方案 |
|---|---|---|
| 單機雙人 | 同一台電腦輪流下，可選擇每回合自動翻轉視角 | 純前端 |
| 連線雙人 | 建立房間 → 分享房號／連結 → 對手加入 | **建議先用 WebRTC P2P（PeerJS）**，不需要自己的伺服器，可直接放 GitHub Pages ❓ |
| AI 對戰 | 入門／中級／高手 三個難度（之後可加「大師」） | 自寫引擎（Alpha-Beta 搜尋 + 置換表 + 靜止搜尋），跑在 Web Worker，不卡畫面 ❓ |

共通功能：悔棋、提示、計時（可關）、棋譜記錄與回放、視角旋轉縮放、2D/3D 視角切換（給想認真下棋的人）。

## 3. 陣營系統（核心賣點）

### 3.1 規則
- 每位玩家開局選一個陣營，整副 16 子都屬於同一國。
- 每個陣營需要：**將帥 1、士 2、象 2、車 2、馬 2、炮 2 → 11 位具名人物 + 1 種兵種**（5 個兵共用一個兵種造型，例如「白毦兵」）。
- 預設對局為 **楚 vs 漢**——正好呼應棋盤上的「楚河漢界」。
- ❓ 是否允許雙方選同一國（例如蜀 vs 蜀，鏡像對決）？

## 4. 特效與演出

### 4.1 一般吃子（每次都會出現，2 秒內結束，不拖節奏）
依「攻擊方棋種」給不同的吃子演出：
- **車**：直線衝撞，目標棋子碎裂成石塊飛散 + 鏡頭震動
- **馬**：躍起踐踏，落地衝擊波
- **炮**：拋物線火球越過炮架，命中後爆炸、火星粒子
- **兵**：刀光一閃，棋子斜切成兩半滑落
- **仕／象／將帥**：各自一個小型招式

加上：短暫子彈時間（slow-mo）、命中時畫面閃白、被吃棋子的人物剪影淡出。
設定中可調「特效強度：完整／精簡／關閉」。

### 4.2 「將軍！」提示
被將軍時棋盤邊緣泛紅光，出現書法字「將軍」+ 戰鼓音效。

### 4.3 絕招（終局全畫面演出，約 5~8 秒，可點擊跳過）
**注意規則細節**：正式象棋裡將帥其實不會被「吃掉」，對局在「將死」或「困斃」時就結束。
本提案的處理方式：**將死發生時，自動演出「最後一擊」**——將死對方的那顆棋子衝向敵方將帥，
畫面暗下 → 人物立繪 + 書法招式名 → 全畫面招式動畫 → 敵方將帥碎裂 → 勝利畫面。

❓ 需確認觸發者：
- **(A) 由「吃掉將帥的那顆棋子」放絕招**（我的理解，也是我推薦的，每位人物都有出場機會）
- (B) 一律由勝方「主帥」放絕招
- (C) 棋子出手 + 主帥收尾，兩段演出

困斃（無子可動）或對方認輸／超時的情況，則由勝方主帥放絕招。

## 5. 棋子造型方案 ❓

| 方案 | 外觀 | 優點 | 缺點 |
|---|---|---|---|
| A. 圓形棋子 + 浮雕人像 | 傳統圓棋，正面是人物浮雕頭像 + 小字「車」 | 最好辨識，下棋不吃力 | 「人物感」較弱 |
| **B. 圓棋底座 + 立體立牌（推薦先做）** | 圓棋上方立一張人物立繪（帶厚度、會微微轉向鏡頭），底座刻棋種字 | 人物感強、美術只需 2D 立繪，成本可控、仍好辨識 | 側面角度較平 |
| C. 全 3D 人偶 | 每位人物獨立 3D 模型，有待機／攻擊動作 | 最酷炫 | 每國 12 個模型 × 動作，製作成本最高 |

建議路線：**先做 B，之後逐步把熱門人物（關羽、項羽…）升級成 C。**
不論哪個方案，棋子上一定保留「車／馬／炮」字樣或圖示，避免玩家看不出棋種。

## 6. 音樂與音效
- **背景音樂**：選單（古琴悠揚）、對局（依陣營：楚＝楚調簫聲、蜀＝古箏、魏＝編鐘戰鼓…）、緊張局面（被將軍時自動加入鼓點）、勝利／失敗。
- **音效**：拿起／落子（木頭或玉石聲）、吃子（依棋種）、將軍、絕招專屬音效、UI 點擊。
- 音量分軌（音樂／音效／語音）可分別調整。
- 素材來源 ❓：免版稅素材庫（Pixabay、Freesound CC0）／AI 生成音樂／委託製作。MVP 可先用程式合成的音效頂著。

## 7. 技術架構

```
xiangqi-3d/
├── src/
│   ├── core/        # 純邏輯：棋盤、走法產生、合法性、將死/困斃/重複局面判定（不依賴畫面，可單元測試）
│   ├── ai/          # AI 引擎（Web Worker）
│   ├── net/         # 連線對戰（PeerJS）
│   ├── render/      # Three.js 3D 場景、棋子、鏡頭
│   ├── fx/          # 粒子、吃子特效、絕招演出、後製（Bloom）
│   ├── audio/       # 音樂與音效管理
│   ├── data/        # 陣營與人物資料（JSON：名字、字、簡介、絕招、立繪路徑）
│   └── ui/          # 選陣營、Tooltip、設定、勝負畫面
├── public/assets/   # 立繪、貼圖、音樂、音效
└── docs/            # 本文件
```

- 語言／建置：**TypeScript + Vite**
- 3D：**Three.js**（+ postprocessing 做發光、景深）
- 動畫：GSAP（鏡頭運鏡、演出時間軸）
- 音訊：Howler.js
- 連線：PeerJS（WebRTC P2P）；未來若要配對、排行榜、觀戰再加 Node.js + Socket.IO 伺服器
- 測試：Vitest（規則引擎一定要有完整測試，例如蹩馬腿、塞象眼、將帥對臉、炮架判斷）
- 部署：GitHub Pages（免費、push 即上線）

人物資料用 JSON 管理，**之後新增陣營只要加資料與美術，不用改程式**。

## 9. 需要你決定的事（彙整）

1. **絕招觸發者**：(A) 吃王的棋子 / (B) 勝方主帥 / (C) 兩段都要？
2. **棋子造型**：先做方案 B（立牌）可以嗎？還是一開始就要全 3D 人偶？
3. **連線方式**：先用 P2P 免伺服器，還是一開始就要伺服器（配對、排行榜）？
4. **AI 強度**：自寫引擎（業餘中等程度，夠一般玩家玩）可以嗎？若要「大師級」可整合開源引擎 Pikafish（WASM），但它是 GPL 授權，整個專案也必須開源。
5. **美術／音樂來源**：AI 生成、免版稅素材、或你有美術資源？
6. **首發陣營**：楚、漢、蜀、魏、吳 這五國 OK 嗎？想加哪些人物或國家？
7. **同國對戰**：允許蜀 vs 蜀嗎？
8. **目標平台**：桌機為主，還是手機也要完整支援？
9. **遊戲名稱**：暫定《楚河漢界：名將對弈》，有其他想法嗎？
